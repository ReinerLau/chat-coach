# 中文回复教练 Skill 回复规则说明

本文供人阅读，说明 [中文回复教练 Skill](../skills/chat-reply/SKILL.md) 中的四条回复规则。Skill 不引用或读取本文，手工比较时也不把本文或示例加入模型输入。

示例取自现有手工测试场景，用于理解规则，不作为固定回复模板。正反例只说明各自场景中的差别，不把某个词或句式列为通用禁令。

## 规则 1：当前意愿

> 行动、表态和承诺以用户明确表达的当前意愿为依据。

适用于候选回复需要表达行动、表态或承诺的场景。判断依据是用户本轮明确表达的选择或倾向。

### 案例 03：本次不参加露营

场景来自 [周末露营](chat-reply-manual-tests.md#03-周末露营)。朋友正在订营位，问是否给用户留一个。

用户意图：这次不想去，想直接说不去，不需要解释原因。

| 类型 | 候选回复 |
| --- | --- |
| 正例 | 这次不去了，你们玩。 |
| 反例 | 这次不去了，你们玩，下次我一定去。 |

正例表达了本次不参加的选择。反例额外承诺了下次参加，但用户没有表达这个当前意愿。问题在于新增的承诺，不在于“一定”这个词本身。

## 规则 2：接话与省略

> 根据前文接话，双方已经知道、对方能够理解的内容允许省略；用户说明用于确定表达方向，不必逐项写进候选回复。

适用于根据聊天上下文判断候选回复需要说出哪些内容。用户说明确定本轮想表达的内容、态度或安排；实际接话时，结合双方已经知道的信息选择说法，必要信息仍要表达完整。

### 参考来源与聊天场景的适配

[human-writing 的“对白在做事”](https://github.com/KKKKhazix/human-writing/blob/main/human-writing/references/fiction.md#对白在做事) 允许人物说一半，并指出双方都知道的背景不会为了读者重新交代。原文讨论虚构作品中的人物对白。

本项目将其中的已知信息与省略原则适配到聊天回复，并增加“用户说明用于确定表达方向”的要求。后者是本项目的适配，原文没有直接规定怎样处理用户说明。候选回复仍依据用户明确表达的当前意愿，不借用虚构创作的权限补造事实或承诺。

省略取决于当前上下文，不要求固定字数、刻意断句或统一添加口头禅。信息已经说清楚时可以省略；对方尚不知道的时间、选择或必要条件应当说清楚。

### 案例 02：约三点喝咖啡

场景来自 [周六的咖啡店](chat-reply-manual-tests.md#02-周六的咖啡店)。双方已经讨论好商场二楼的咖啡店，对方正在问几点到合适。

用户意图：两点半之前有事，三点能到那家店，想约三点。

| 类型 | 候选回复 |
| --- | --- |
| 省略已知信息的示例 | 三点吧，店里见。 |
| 逐项交代的示例 | 我两点半之前有事，三点能到商场二楼那家咖啡店，我们约三点见。 |

第一条保留了对方需要知道的三点安排，地点由前文确定。第二条事实也符合用户说明，但重新交代了地点和此前的个人安排。在这个场景中，对方只需要确认见面时间；用户两点半之前有事，是判断可约时间的依据，不必逐项写进回复。完整交代本身不构成违规，是否保留取决于对方是否需要这些信息。

### 案例 05：收到生日礼物

场景来自 [生日的钥匙扣](chat-reply-manual-tests.md#05-生日的钥匙扣)。朋友记得用户逛街时看过那只橘猫，寄来作为生日礼物。

用户意图：很喜欢这个礼物，也有点感动。

| 类型 | 候选回复 |
| --- | --- |
| 根据前文表达的示例 | 太喜欢了，你居然还记着。 |
| 逐项交代的示例 | 谢谢你，真的好喜欢，你连我回头看那一眼都记得，有点感动了。 |

第一条直接表达喜欢，并通过对朋友记得这件事的反应表达感动，具体细节由前文补足。第二条依次交代感谢、喜欢、回顾细节和感动，更接近把用户说明逐项展开。“有点感动了”可以是自然表达，不是禁用句；这里比较的是当前上下文中哪些内容已经能够被对方理解。两条都不是自然度的标准答案，具体感受由用户手工判断。

### 案例 07：表达高兴并约吃饭

场景来自 [面试之后](chat-reply-manual-tests.md#07-面试之后)。朋友拿到了工作机会，想在今晚吃点好的。

用户意图：替朋友高兴，今晚七点以后有空，可以一起吃饭。

| 类型 | 候选回复 |
| --- | --- |
| 正例 | 太好了！我七点以后有空，一起吃？ |
| 过度省略的反例 | 恭喜啊！ |

对方尚不知道用户七点以后有空、愿意一起吃饭，这些安排不能依靠前文推断。正例表达了高兴并保留时间和吃饭邀请；过度省略的回复只剩祝贺，遗漏了组合意图。省略只适用于对方能够理解的内容，不能为了缩短回复删掉必要信息。

## 规则 3：接话方向

> 根据用户意图接话，不必逐项回答对方的问题，可以接其中一个话头、回应情绪或反问。

规则 2 说明哪些内容可以省略，规则 3 说明可以怎样选择接话方向。[human-writing 的“对白在做事”](https://github.com/KKKKhazix/human-writing/blob/main/human-writing/references/fiction.md#对白在做事) 允许人物答非所问；本项目将其适配为依据用户意图选择接话方向。

例如，对方问“怎么还没睡”，用户想继续闲聊，可以回复“你不也没睡，刚在干嘛？”。没有直接解释未睡的原因，也能延续话题。接话方向以用户意图为依据，不把回避问题或反问作为固定风格。

## 规则 4：情绪与态度的表达

> 情绪和态度可以通过符合上下文的接话表达，不必逐项自述。

适用于用户已经明确本轮想表达的情绪或态度的场景。候选回复可以回应对方刚说的具体内容，让对方从这句回应中感受到用户的情绪和态度。规则 2 关注哪些信息可以省略，规则 4 关注情绪和态度可以怎样表达。

直接说出感受仍然可以自然。新规则提供表达选择，不要求把情绪藏起来，也不把“我很生气”“有点感动”等说法列为禁用句。表达方式仍以用户意图为依据，不能把明确拒绝改成犹豫、把认真表达不满改成玩笑，或遗漏对方需要知道的时间和安排。

### 案例 04：陪朋友吐槽

场景来自 [半夜改方案](chat-reply-manual-tests.md#04-半夜改方案)。朋友被客户要求增加方案的“呼吸感”，追问具体怎么改时，客户又让她自己判断。

用户意图：陪她吐槽一会儿。

| 类型 | 候选回复 |
| --- | --- |
| 直接表达感受的示例 | 听着就烦，你也太难了。 |
| 通过接话表达的示例 | 他倒是省心，连想怎么改都交给你了。 |

第二条接着吐槽客户把问题推回来的做法，让朋友感受到用户在陪她吐槽。第一条也能表达体谅，不因为直接说出感受就不自然。这里比较的是能否接住当前话题，不要求固定使用讽刺或玩笑。

### 案例 05：回应朋友的用心

场景和用户意图与 [规则 2 中的生日礼物案例](#案例-05收到生日礼物) 相同：用户很喜欢礼物，也有点感动。

“太喜欢了，你居然还记着。”直接表达了喜欢，又通过回应朋友记得那只橘猫的细节表达感动。对方能够从这句反应中感受到自己的用心被看见，不必再单独补一句“我有点感动”。如果用户想直接说出感动，也可以保留。

### 案例 13：说清楚为什么生气

场景来自 [临时取消的见面](chat-reply-manual-tests.md#13-临时取消的见面)。对方在用户已经上车后临时取消见面，还说“不就一顿饭吗，别这么认真”。

用户意图：很生气，在意的是对方临时取消又不当回事，想把这点说清楚。

| 类型 | 候选回复 |
| --- | --- |
| 直接表达感受的示例 | 我很生气，你临时取消还不当回事。 |
| 通过接话表达的示例 | 我都上车了你才取消，最后还成我太认真了？ |

第二条回应已经上车才被取消、又被指责太认真的具体经过，表达了生气及其原因。两种表达都保留用户的不满；如果改成“行吧，下次再说”，即使更短，也没有表达用户在意的事。

## 规则 2 的手工比较

两版使用相同的 Skill 结构，基线版临时移除新回复规则 2、仅保留规则 1，实验版保留规则 1 和新的接话与省略规则。两版均不包含旧规则。

进行这项比较时，两版均临时移除规则 3、4，以保持只比较规则 2 的范围。

固定模型、测试输入和用户意图，每次使用新会话，仅调用 chat-reply；[手工测试集](chat-reply-manual-tests.md) 中的案例 01–05、07 每版各试三次。文档及示例不加入模型输入，现有测试输入和空白记录区保持原样。

由用户观察接话是否自然、是否减少机械复述，并确认案例 01、02 的时间和一起吃饭或见面安排、案例 03 的明确拒绝、案例 04 的陪伴吐槽、案例 05 的喜欢与感动、案例 07 的组合意图完整表达。情绪可以通过符合上下文的说法表达，不要求逐字复述用户说明。原始输出、判断与备注由用户记录，不代填测试结论。

改善且无遗漏才保留新规则 2，否则撤回新规则 2。本轮不运行自动化回复评测，也不输出评测报告。

## 规则 4 的手工比较

基线版保留规则 1–3、临时移除规则 4，实验版保留全部四条规则，其余 Skill 内容一致。

固定模型、测试输入和用户意图，每次使用新会话，仅调用 chat-reply；使用 [手工测试集](chat-reply-manual-tests.md) 中的案例 04、05、13，每版各试三次。由用户比较候选回复能否通过符合上下文的接话表达陪伴吐槽、喜欢与感动、生气及其原因。直接表达感受也可以符合用户意图，判断不以是否出现情绪词为标准。

同时用案例 03、07 每版各试三次，确认明确拒绝没有变成犹豫或新增承诺，七点以后的时间和一起吃饭的安排完整表达。文档及示例不加入模型输入，现有测试输入和空白记录区保持原样；原始输出、判断与备注由用户记录，不代填测试结论。

由用户手工判断是否改善且无意图遗漏，再决定是否保留规则 4。不运行自动化回复评测，也不输出评测报告。
