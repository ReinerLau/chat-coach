# 中文回复教练 Skill 回复规则说明

本文供人阅读，说明 [中文回复教练 Skill](../skills/chat-reply/SKILL.md) 中的两条回复规则。Skill 不引用或读取本文，手工比较时也不把本文或示例加入模型输入。

示例取自现有手工测试场景，用于理解规则，不作为固定回复模板。正反例只说明各自场景中的差别，不把某个词或句式列为通用禁令。

## 规则 1：当前意愿

> 行动、表态和承诺以用户明确表达的当前意愿为依据。

适用于候选回复需要表达行动、表态或承诺的场景。判断依据是用户本轮明确表达的选择或倾向。

### 案例 03：本次不参加露营

场景来自 [周末露营](chat-reply-manual-tests.md#03-周末露营)。朋友正在订营位，问是否给用户留一个。

用户意图：这次不想去，想直接说不去，不需要解释原因。

| 类型 | 候选回复 |
| --- | --- |
| 正例 | 这次不去了，你们玩。 |
| 反例 | 这次不去了，你们玩，下次我一定去。 |

正例表达了本次不参加的选择。反例额外承诺了下次参加，但用户没有表达这个当前意愿。问题在于新增的承诺，不在于“一定”这个词本身。

## 规则 2：表达重点

> 候选回复围绕一个表达重点组织内容。

适用于判断一条候选回复怎样取舍和组织内容。先看这条回复主要想表达什么，再看其中的细节、情绪和安排是否共同服务于这个重点。

### 参考来源与聊天场景的适配

[human-writing 的“短文与社交内容”](https://github.com/KKKKhazix/human-writing/blob/main/human-writing/references/formats.md#短文与社交内容) 提出“只留一个主要任务”，随后列举交代消息、讲观察、给判断、留下细节等表达功能，并讨论短内容的开头、收尾和改写。

结合这段上下文，我们把它理解为短内容的表达集中度，并适配成当前规则。这是本项目对聊天场景的解释；原文没有直接规定微信回复只能有一个话题，也没有要求只能表达用户意图中的一件事。

### 案例 05：收到生日礼物

场景来自 [生日的钥匙扣](chat-reply-manual-tests.md#05-生日的钥匙扣)。朋友记得用户逛街时看过那只橘猫，寄来作为生日礼物。

用户意图：很喜欢这个礼物，也有点感动。

| 类型 | 候选回复 |
| --- | --- |
| 正例 | 你连这个都记得啊，收到好开心。 |
| 反例 | 你连这个都记得啊，收到好开心。原来真正的友情，就是把这些小事放在心上。 |

两条回复都围绕同一件礼物展开。正例的细节和情绪共同表达收到礼物的开心与感动。反例在这个表达已经完成后，又加入总结友情意义的功能，使短回复承担了额外的表达任务。差别在于内容怎样组织，不在于是否换了话题，也不把“友情”这个词或所有感慨列为禁令。

### 案例 07：表达高兴并约吃饭

场景来自 [面试之后](chat-reply-manual-tests.md#07-面试之后)。朋友拿到了工作机会，想在今晚吃点好的。

用户意图：替朋友高兴，今晚七点以后有空，可以一起吃饭。

| 类型 | 候选回复 |
| --- | --- |
| 正例 | 太好了！我七点以后有空，一起吃？ |
| 误读规则的反例 | 恭喜啊！ |

这组对照检查应用边界，不用于证明“恭喜啊”违反表达重点规则。正例的高兴、空闲时间和吃饭邀请共同围绕庆祝朋友拿到工作机会展开。误读后的回复只保留祝贺，遗漏了用户想表达的吃饭安排。一个表达重点可以包含多句内容和组合意图，不能为了形式上的单一而删掉必要信息。

## 本轮手工比较

两版使用相同的 Skill 结构，基线版临时移除回复规则 2、仅保留规则 1，实验版保留规则 1、2。

固定模型、测试输入和用户意图，每次使用新会话，仅调用 chat-reply；[手工测试集](chat-reply-manual-tests.md) 中的案例 01、02、04、05、07 每版各试三次。由用户判断自然度和信息完整性，观察内容是否围绕表达重点组织，重点检查案例 07 是否遗漏组合意图。

改善且无遗漏才保留规则 2，否则撤回规则 2。本轮不运行自动化回复评测，也不输出评测报告。
