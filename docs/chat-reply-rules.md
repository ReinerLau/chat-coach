# 中文回复教练 Skill 回复规则说明

本文供人阅读，说明 [中文回复教练 Skill](../skills/chat-reply/SKILL.md) 中的四条回复规则。Skill 不引用或读取本文，手工比较时也不把本文或示例加入模型输入。

示例取自现有手工测试场景，用于理解规则，不作为固定回复模板。正反例只说明各自场景中的差别，不把某个词或句式列为通用禁令。

## 规则 1：当前意愿

> 行动、表态和承诺以用户明确表达的当前意愿为依据。

适用于候选回复需要表达行动、表态或承诺的场景。判断依据是用户本轮明确表达的选择或倾向。

### 案例 03：本次不参加露营

场景来自 [周末露营](chat-reply-manual-tests.md#03-周末露营)。朋友正在订营位，问是否给用户留一个。

用户意图：这次不想去，想直接说不去，不需要解释原因。

| 类型 | 候选回复 |
| --- | --- |
| 正例 | 这次不去了，你们玩。 |
| 反例 | 这次不去了，你们玩，下次我一定去。 |

正例表达了本次不参加的选择。反例额外承诺了下次参加，但用户没有表达这个当前意愿。问题在于新增的承诺，不在于“一定”这个词本身。

## 规则 2：接话与省略

> 根据前文接话，省略双方已知且本轮无需重申的细节；用户说明用于确定表达方向，按用户意图取舍需要说出的内容。

适用于根据聊天上下文判断候选回复需要说出哪些内容。用户说明确定本轮想表达的内容、态度或安排，不是逐项写入候选回复的清单。生成时结合前文判断哪些意思已经传达、哪些还需要说出，保留必要信息，省去仅用于解释已有表达的补充句。

### 参考来源与聊天场景的适配

[human-writing 的“对白在做事”](https://github.com/KKKKhazix/human-writing/blob/main/human-writing/references/fiction.md#对白在做事) 允许人物说一半，并指出双方都知道的背景不会为了读者重新交代。原文讨论虚构作品中的人物对白。

本项目将其中的已知信息与省略原则适配到聊天回复，并增加“用户说明用于确定表达方向”的要求。后者是本项目的适配，原文没有直接规定怎样处理用户说明。候选回复仍依据用户明确表达的当前意愿，不借用虚构创作的权限补造事实或承诺。

省略取决于当前上下文，不要求固定字数、刻意断句或统一添加口头禅。双方已知且本轮无需重申的细节应当省略；对方尚不知道的时间、选择或必要条件应当说清楚。已知内容仍可用于回应对方、明确表态或消除误解，判断依据是本轮表达需要，而不是是否提供新信息。

### 案例 02：约三点喝咖啡

场景来自 [周六的咖啡店](chat-reply-manual-tests.md#02-周六的咖啡店)。双方已经讨论好商场二楼的咖啡店，对方正在问几点到合适。

用户意图：两点半之前有事，三点能到那家店，想约三点。

| 类型 | 候选回复 |
| --- | --- |
| 省略已知信息的示例 | 三点吧，店里见。 |
| 逐项交代的示例 | 我两点半之前有事，三点能到商场二楼那家咖啡店，我们约三点见。 |

第一条保留了对方需要知道的三点安排，地点由前文确定。第二条事实也符合用户说明，但重新交代了地点和此前的个人安排。在这个场景中，对方只需要确认见面时间；用户两点半之前有事，是判断可约时间的依据。按修订后的规则，应省去本轮无需重申的地点细节，并按约三点的用户意图取舍个人安排的说明。

### 案例 05：收到生日礼物

场景来自 [生日的钥匙扣](chat-reply-manual-tests.md#05-生日的钥匙扣)。朋友记得用户逛街时看过那只橘猫，寄来作为生日礼物。

用户意图：很喜欢这个礼物，也有点感动。

| 类型 | 候选回复 |
| --- | --- |
| 根据前文表达的示例 | 你居然还记着，谢谢啊。 |
| 逐项交代的示例 | 谢谢你，真的好喜欢，你连我回头看那一眼都记得，有点感动了。 |

前文的“刚拆，居然是那只橘猫”“已经挂钥匙上了”已经表达了喜欢。第一条通过“你居然还记着”带出被惦记的感动，用“谢谢啊”完成感谢；双方都知道的逛街细节由前文补足。第二条依次交代感谢、喜欢、回顾细节和感动，更接近把用户说明逐项展开。“有点感动了”可以是自然表达，不是禁用句；这里应省去的是当前上下文中已足以传达、又无需展开的意思。示例只说明本场景的取舍，不是固定模板或自然度的标准答案，具体感受由用户手工判断。

### 案例 07：表达高兴并约吃饭

场景来自 [面试之后](chat-reply-manual-tests.md#07-面试之后)。朋友拿到了工作机会，想在今晚吃点好的。

用户意图：替朋友高兴，今晚七点以后有空，可以一起吃饭。

| 类型 | 候选回复 |
| --- | --- |
| 正例 | 太好了！我七点以后有空，一起吃？ |
| 过度省略的反例 | 恭喜啊！ |

对方尚不知道用户七点以后有空、愿意一起吃饭，这些安排不能依靠前文推断。正例表达了高兴并保留时间和吃饭邀请；过度省略的回复只剩祝贺，遗漏了组合意图。省略只适用于对方能够理解的内容，不能为了缩短回复删掉必要信息。

## 规则 3：接话方向

> 根据用户意图接话，不必逐项回答对方的问题，可以接其中一个话头、回应情绪或反问。

规则 2 说明哪些内容应按本轮表达需要取舍，规则 3 说明可以怎样选择接话方向。[human-writing 的“对白在做事”](https://github.com/KKKKhazix/human-writing/blob/main/human-writing/references/fiction.md#对白在做事) 允许人物答非所问；本项目将其适配为依据用户意图选择接话方向。

例如，对方问“怎么还没睡”，用户想继续闲聊，可以回复“你不也没睡，刚在干嘛？”。没有直接解释未睡的原因，也能延续话题。接话方向以用户意图为依据，不把回避问题或反问作为固定风格。

## 规则 4：情绪与态度的表达

> 结合上下文回应具体话头，让情绪和态度从接话中带出；前文或接话已经足以传达的，不再补写同义的情绪自述或解释。给情绪命名或描述自身的内心感受，都属于情绪自述。需要明确表态、消除误解或展开情绪时，直接说清楚。

适用于用户已经明确本轮想表达的情绪或态度的场景。用户提供情绪是确定表达方向，不等于要求把每一种感受单独说出来。结合前文和本轮接话判断情绪是否已经足以传达，表达足够让对方理解时就收住。规则 2 关注内容取舍，规则 4 关注情绪和态度的表达是否还需要补充。

情绪自述的判断依据是表达是否在描述自身的内心感受，适用于高兴、感动、委屈、烦躁、焦虑等情绪，不限于某一种情绪或是否出现情绪名称。

用户无需主动要求含蓄，表达程度由用户意图、双方关系、聊天语气和当前场景共同决定。含蓄、简短不是统一要求；需要明确表态、消除误解或展开情绪时，应直接说清楚，不必都等用户主动提出。直接说出感受仍然可以自然，“我很生气”“有点感动”等说法不是禁用句。不能把明确拒绝改成犹豫、把认真表达不满改成玩笑，或遗漏对方需要知道的时间和安排。

### 案例 04：陪朋友吐槽

场景来自 [半夜改方案](chat-reply-manual-tests.md#04-半夜改方案)。朋友被客户要求增加方案的“呼吸感”，追问具体怎么改时，客户又让她自己判断。

用户意图：陪她吐槽一会儿。

| 类型 | 候选回复 |
| --- | --- |
| 直接表达感受的示例 | 听着就烦，你也太难了。 |
| 通过接话表达的示例 | 他倒是省心，连想怎么改都交给你了。 |

第二条接着吐槽客户把问题推回来的做法，让朋友感受到用户在陪她吐槽。第一条也能表达体谅，不因为直接说出感受就不自然。这里比较的是能否接住当前话题，不要求固定使用讽刺或玩笑。

### 案例 05：回应朋友的用心

场景和用户意图与 [规则 2 中的生日礼物案例](#案例-05收到生日礼物) 相同：用户很喜欢礼物，也有点感动。

“你居然还记着，谢谢啊。”回应朋友的用心并表达感谢，喜欢礼物的意思由前文承接，感动由这句接话带出。用户仅说明“很喜欢，也有点感动”，不等于要求展开这两种感受；在本场景中，无需再补一句“我有点感动”或把回头看那一眼的经过重新说全。若用户意图或场景需要进一步表达感受，再展开。

“谢谢你呀，这下每天出门都有小猫陪着了”接着钥匙扣的话头表达喜欢，也是可接受的接话方向。“谢谢你呀，有种被你悄悄放在心上的感觉”则在描述自身的内心感受，即使没有使用“感动”一词，仍属于情绪自述。在本场景中，优先让情绪从具体接话中带出；这不要求所有候选回复都回应“还记着”，也不以是否出现情绪词判断是否符合规则。

### 案例 13：说清楚为什么生气

场景来自 [临时取消的见面](chat-reply-manual-tests.md#13-临时取消的见面)。对方在用户已经上车后临时取消见面，还说“不就一顿饭吗，别这么认真”。

用户意图：很生气，在意的是对方临时取消又不当回事，想把这点说清楚。

| 类型 | 候选回复 |
| --- | --- |
| 直接表达感受的示例 | 我很生气，你临时取消还不当回事。 |
| 通过接话表达的示例 | 我都上车了你才取消，最后还成我太认真了？ |

第二条回应已经上车才被取消、又被指责太认真的具体经过，表达了生气及其原因。两种表达都保留用户的不满；如果改成“行吧，下次再说”，即使更短，也没有表达用户在意的事。

## 表达取舍修订的手工比较

基线版使用本次修订前的完整四条规则，实验版保留规则 1、3 并采用修订后的规则 2、4；其余 Skill 内容与流程一致，不临时移除任何规则。记录两版的 commit，整体比较表达取舍的变化，不把改善或退化单独归因于第 4 条。

固定模型、测试输入和用户意图，每次使用新会话，仅以 `$chat-reply` 调用；使用 [手工测试集](chat-reply-manual-tests.md) 中的案例 03、05、06、07、13，每版各试三次。只复制“测试输入”代码块，本文、示例及手工验收说明不加入模型输入。现有测试输入和空白记录区保持原样，原始输出、判断与备注由用户记录，不代填测试结论。

- 案例 05：用户无需主动要求含蓄；前文已经表达喜欢时，接话能带出感动并完成感谢，省去机械交代两种情绪或重述逛街细节的补充句。不要求复现示例，也不以是否出现情绪词为标准。
- 案例 03、13：明确拒绝没有变成犹豫或新增承诺，表达不满时保留临时取消又不当回事这一原因，不因省略而弱化用户意图。
- 案例 07：七点以后的时间和一起吃饭的安排完整表达。
- 案例 06：用户想讲述旅行经历时正常展开，保留其想分享的轮渡停航、改坐大巴、找错花盆以及老板开门送橘子的经过，不一律压短。

由用户手工判断是否改善且无意图遗漏，再决定是否保留本次修订。不运行自动化回复评测，也不输出评测报告。
