# 回复 Skill 测试用例

这份文档把 15 个固定测试用例整理成中文阅读版，帮助你理解每道题在考什么。评测仍以 [原始用例 JSON](../skills/chat-reply/evals/cases.json) 为唯一正式来源；三个 Agent 的分工、评分和通过门槛见 [评测流程](../skills/chat-reply/EVAL.md)。修改正式用例后，需要同步更新这份阅读版，保持用例顺序和内容一致。返回 [README](../README.md)。

每道题包含聊天上下文、用户需求、回复数量、考察重点和失败条件。用例 ID 用于对应原始 JSON 和评测结果。本页不提供标准答案，评测也不要求回复使用固定措辞。

## 怎么读考察重点

| 考察重点 | 检查什么 |
| --- | --- |
| 材料依据 | 是否只使用明确提供的信息，有没有编造事实、情绪、动机或承诺。 |
| 完成当前任务 | 是否完成这一轮真正需要的回答、确认、拒绝或其他沟通任务。 |
| 表达自然 | 用词、正式程度和情绪强度是否符合当前聊天。 |
| 及时停止 | 任务完成后是否收住，有没有多余建议、总结或强行续聊。 |
| 候选多样性 | 多个候选是否提供不同沟通思路，而不只是替换近义词。 |

失败条件分为两类：

- **严重错误**：对应 JSON 中的 `critical: true`。使用 Skill 的回复只要命中一项，整轮评测就不能通过。
- **一般问题**：对应 `critical: false`，会参与质量判断，但命中一项不代表整轮自动失败；完整通过条件见评测流程。

## 固定用例

### 1. 回应“到了”时不补充未知状态

**用例 ID**：`material-boundary-arrived`

**聊天上下文**：

> 对方：到了

**用户需求**：给出一条自然回复。

**回复数量**：1 条候选回复。

**考察重点**：材料依据、及时停止。

**失败条件**：

- **严重错误**：凭空补充对方已经安全到家、很累、路上辛苦等未出现的信息。
- **一般问题**：在简单接住即可时强行追问新问题。

### 2. 答应吃饭邀约并确认时间

**用例 ID**：`action-overload-dinner`

**聊天上下文**：

> 对方：晚上吃饭吗

**用户需求**：你想去，但时间还没定。给出一条自然回复。

**回复数量**：1 条候选回复。

**考察重点**：完成当前任务、及时停止。

**失败条件**：

- **一般问题**：一条消息里同时确认、定餐厅、定菜、定交通等多个没有必要的动作。
- **严重错误**：凭空指定对方没提过的餐厅、地点或活动。

### 3. 接住到家通知后及时收住

**用例 ID**：`stop-home`

**聊天上下文**：

> 对方：我到家了

**用户需求**：给出一条自然回复。

**回复数量**：1 条候选回复。

**考察重点**：及时停止、表达自然。

**失败条件**：

- **一般问题**：在信息已闭合时追加照顾身体、安全提醒、总结或建议。
- **严重错误**：凭空判断对方很累、害怕、开心等情绪。

### 4. 自然回应“怎么突然问这个”

**用例 ID**：`casual-sudden-question`

**聊天上下文**：

> 对方：哈哈哈
>
> 对方：你怎么突然问这个

**用户需求**：给出一条自然回复，语气跟随当前聊天。

**回复数量**：1 条候选回复。

**考察重点**：表达自然、完成当前任务。

**失败条件**：

- **一般问题**：明显比上下文正式、书面或解释过度。
- **严重错误**：编造自己之前并未提供的复杂动机或背景。

### 5. 认真回应明确的边界反馈

**用例 ID**：`serious-boundary`

**聊天上下文**：

> 对方：这件事我真的不太舒服，我觉得你越界了

**用户需求**：给出一条稳妥回复。

**回复数量**：1 条候选回复。

**考察重点**：完成当前任务、表达自然。

**失败条件**：

- **严重错误**：用调侃、卖萌或轻浮方式绕开明确的边界反馈。
- **严重错误**：替自己编造理由、动机或事实来反驳对方。

### 6. 确认已经定好的时间

**用例 ID**：`simple-confirmation`

**聊天上下文**：

> 对方：行，那就明天七点

**用户需求**：给出一条自然回复。

**回复数量**：1 条候选回复。

**考察重点**：及时停止、表达自然。

**失败条件**：

- **一般问题**：已经确认的安排被再次展开成多余讨论或追问。

### 7. 回应烦恼但不猜测原因

**用例 ID**：`low-mood`

**聊天上下文**：

> 对方：最近有点烦

**用户需求**：给出一条克制、自然的回复。

**回复数量**：1 条候选回复。

**考察重点**：材料依据、完成当前任务、表达自然。

**失败条件**：

- **严重错误**：没有材料却判断对方为什么烦、问题有多严重或具体发生了什么。
- **一般问题**：未经请求直接给出一串解决方案。

### 8. 澄清时使用已有的“刚在忙”信息

**用例 ID**：`use-explicit-prior-material`

**聊天上下文**：

> 我：没事，我刚在忙
>
> 对方：你是不是生气了

**用户需求**：根据已有上下文给出一条回复。

**回复数量**：1 条候选回复。

**考察重点**：材料依据、完成当前任务。

**失败条件**：

- **严重错误**：忽略已有的“刚在忙”信息，反而另编原因。
- **一般问题**：为简单澄清补出一大段未出现的经历或情绪说明。

### 9. 礼貌拒绝邀约但不编造理由

**用例 ID**：`polite-refusal-no-excuse`

**聊天上下文**：

> 对方：今晚出来吗

**用户需求**：你今晚不想出去，但没有提供任何具体原因。给出一条礼貌回复。

**回复数量**：1 条候选回复。

**考察重点**：材料依据、完成当前任务。

**失败条件**：

- **严重错误**：编造加班、生病、已有约会、家里有事等理由。
- **一般问题**：为了拒绝而做过多承诺或安排。

### 10. 拒绝吃饭邀约但不擅自承诺改天再约

**用例 ID**：`do-not-invent-user-details`

**聊天上下文**：

> 对方：今晚出来吃饭吗

**用户需求**：你不想去，除此之外没有提供理由或改天再约的打算。给出一条自然回复。

**回复数量**：1 条候选回复。

**考察重点**：材料依据、完成当前任务、及时停止。

**失败条件**：

- **严重错误**：替用户编造疲惫、加班、生病等未提供的拒绝理由。
- **严重错误**：替用户承诺改天请客或另约时间。

### 11. 回答时间而不重复共同背景

**用例 ID**：`shared-background-no-repetition`

**聊天上下文**：

> 此前已确认：周六搬家，对方会来帮忙。
>
> 对方：几点过去？

**用户需求**：你已确定十点开始。根据上下文给出一条自然回复。

**回复数量**：1 条候选回复。

**考察重点**：材料依据、表达自然、及时停止。

**失败条件**：

- **一般问题**：无助于消歧或确认，却重新复述双方已经知道的搬家和帮忙背景。
- **一般问题**：没有回答对方当前询问的时间。

### 12. 优先回答消息中的直接问题

**用例 ID**：`select-relevant-point`

**聊天上下文**：

> 对方：今天忙死了，午饭都没吃，刚下班。你到店了吗

**用户需求**：你已经到店。给出一条自然回复。

**回复数量**：1 条候选回复。

**考察重点**：完成当前任务、表达自然、及时停止。

**失败条件**：

- **一般问题**：机械逐项复述或回应对方的忙碌、没吃饭和下班等背景，导致当前到店确认被淹没。
- **一般问题**：没有回答是否到店。

### 13. 为吃饭邀约提供四个不同思路

**用例 ID**：`candidate-diversity-dinner`

**聊天上下文**：

> 对方：晚上吃饭吗

**用户需求**：你愿意去。给出 4 个不同思路的候选回复。

**回复数量**：4 条候选回复。

**考察重点**：候选多样性、完成当前任务、表达自然。

**失败条件**：

- **一般问题**：4 个候选只是同一句话替换语气词或近义词，没有真实策略差异。
- **严重错误**：候选中凭空添加具体餐厅、地点、菜品或背景。

### 14. 回应晚安后结束聊天

**用例 ID**：`goodnight-stop`

**聊天上下文**：

> 对方：晚安

**用户需求**：给出一条自然回复。

**回复数量**：1 条候选回复。

**考察重点**：及时停止、表达自然。

**失败条件**：

- **一般问题**：在明确收尾信号后重新开启新话题或连续提问。

### 15. 接受道歉但不扩写争执或说教

**用例 ID**：`accept-apology`

**聊天上下文**：

> 对方：刚刚我语气不太好，对不起

**用户需求**：你愿意接受道歉。给出一条自然回复。

**回复数量**：1 条候选回复。

**考察重点**：完成当前任务、表达自然、及时停止。

**失败条件**：

- **严重错误**：扩写对方未提到的具体伤害、争执经过或心理状态。
- **一般问题**：接受道歉后追加说教、总结关系或长篇人生建议。
