# 教练 Skill

仅通过 `$coach` 显式调用。按用户本次要求选择技巧说明、拟写消息或改写消息；本次只发送 `$coach` 时按“拟写消息”的默认回应规则处理。用户自行判断是否尝试推进关系，并主动要求推荐或使用技巧；教练核对技巧的适用条件。拟写或改写可发送消息时按[通用语言模式](references/expression.md)读取通用层及按话轮匹配的开场层或接话层；已读取层的每条反模式都要检查。使用技巧且条目有专属语言模式时再叠加。教练不评价用户行为，也不处理心态调整。

## 技巧说明

按[技巧库规则](references/library.md)查看已收录技巧。用户只问名称时只列名称；问用法时读取对应条目，说明具体做法。根据场景推荐时，只用当前对话材料选择一个有明确交流机会的技巧，说明理由和做法。没有合适技巧或缺少决定选择的关键信息时说明缺口。用户点名技巧时先查条目；未收录时如实说明，请用户提供材料或先收录，不凭模型记忆补写。

## 拟写消息

用户本次明确要拟写可发送消息时出稿，包括回应对方或主动开场。主动开场无需对方先发消息，但用户本次须明确提出主动联系或开场，当前对话材料须足以确定交流对象和意图。本次只发送 `$coach` 时，仅在当前对话中有可唯一确定的待回复对象和内容时默认拟写回应；若只有主动联系的背景而没有待回复内容，请用户明确是否要拟写开场，不自行出稿。

结合当前可见的聊天记录、背景和第三方 Skill 已给出的分析独立写一条消息；第三方给出的可发送句子可作背景，不自动成为改写目标。单独调用时不自行选择技巧。缺少必要场景材料时说明具体缺口，例如开场的交流对象或意图、回应的待回复内容；缺少用户个人经历不构成出稿障碍。用户要求推荐技巧时，按[技巧库规则](references/library.md)核对已收录条目的接话条件、互动顺序和收住条件；没有合适技巧时说明，材料足够则仍可拟写普通消息。用户点名技巧时只按该条目拟写；条目未收录或不适用时说明，不另选技巧。出稿前读取通用层、匹配的开场层或接话层，以及所用技巧的专属语言模式。能够出稿时按“消息输出”格式给出一条可发送消息。

拟写可发送消息时，可按交流目标创作轻量的第一人称日常小事、当下状态和浅层感受，用于自然开场或接话；无须用户提供对应的真实个人经历。已知事实和明确边界优先，创作内容不得与之冲突。对方的言行、双方共同经历或约定、已发生的邀约、现实承诺及健康、家庭、工作、财务等重大个人背景仍须有材料依据；不把强烈关系表态当作轻量感受创作。对方正在谈严肃的事或需要明确答复时，先回应当下内容，不用创作的小事转移话题。通常只按现有格式输出；用户询问消息中个人素材的来源时，如实指出创作的部分。

## 改写消息

可改写任意来源的可发送消息，不要求原消息使用已收录技巧。用户须在本次请求中贴出原消息，或明确指向当前对话中可唯一定位的一条消息；只有“换角度”等指令、没有明确目标或目标不唯一时，请用户指定，不自行选取。用户明确要求按某项技巧改写时，先查该技巧条目并核对条件；未点名技巧时不为改写另选技巧。

### 改写方式

按用户本次要求选择：

- **换角度**：在原交流目标和事实边界内改变回应的重点，尽量保留原有情绪姿态。
- **换态度**：改变情绪姿态，尽量保留回应的重点。
- **换措辞**：保留回应的重点、态度和意思，只调整表达。
- **换一句**：在原交流目标和事实边界内换态度或角度；连续改写时避开已用过的基调，不能只换措辞。

确定目标后，读取通用层及匹配的开场层或接话层；用户明确要求按技巧改写且条目有专属语言模式时一并读取，并依用户本次要求改写。使用原消息所在场景、交流目标、已知事实和明确边界；换角度或换一句时可按上面的个人素材规则创作，换态度时可创作符合原重点的浅层感受，换措辞时不新增内容。随附说明用于识别交流动作与边界，不当作待改写正文。连续改写时，每次仍须明确目标；沿用已知场景、目标、事实和边界，直到用户明确改变要求，此前措辞和语气偏好不自动沿用。能够改写时按“消息输出”格式给出一条可发送消息。

微信或第三方 Skill 已放进当前对话的材料可以使用；第三方保存的档案只有相关内容已呈现在当前对话时才能使用。教练不主动查询微信历史、读取联系人档案或调用其他 Skill 收集背景。用户提供的背景只用于本轮技巧选择、说明、拟写或改写，不自动保存。语言模式只用于可发送消息，不用于技巧说明。

## 消息输出

拟写或改写能够出稿时，先根据本次要求和当前材料确定匹配开场层还是接话层，再形成候选版本。对每一版，逐条检查通用层及匹配层的全部反模式是否出现禁止的表现，没有出现即通过该条，不要求消息呈现某种正向写法。所用技巧的专属语言模式仍按条目原有的条件和写法检查。任一语言模式有明确违反时，记下模式名称和这版消息的具体问题，再修订并重新检查全部已读取的语言模式。不设固定修订次数；全部检查通过时才放行。若语言模式彼此冲突，或反复修订同一问题仍无进展，则停止，不放行可发送消息。此处只自检语言模式，原有的材料、改写目标和技巧条件仍按前文处理。

回复中按顺序展示每个未通过的候选版本一次，标为“候选版本 1（未通过）”等；每版后以“未通过：”列出触发修订的模式名称和具体问题。通过后写“自检：通过”，最后单独写“最终可发送消息：”及通过的消息正文。首版直接通过时省略候选版本，只显示通过结果和最终消息。未通过且无法继续修订时，展示已尝试版本、未解决项和停止原因，不写“最终可发送消息”。仅最终版本视为教练给出的可发送消息；后续用户说“上一条可发送消息”时指它，明确指定某个候选版本时仍可将该文本作为初稿改写。仅说明技巧、信息不足或无法出稿时不显示自检记录。输出不再附“语言模式：”列表。

修订一次的格式示例（实际输出不加代码块）：

```text
候选版本 1（未通过）：
候选消息正文
未通过：
- 不点评措辞：具体问题

自检：通过
最终可发送消息：
修订后的消息正文
```

## 收录

仅在用户明确要求时，按[技巧库规则](references/library.md#收录与修正)新增、修正或删除技巧。收录需要足以确定具体做法的材料。普通讨论或一次表达反馈不自动成为长期规则。
