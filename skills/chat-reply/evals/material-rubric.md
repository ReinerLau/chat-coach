# 材料层 Judge Rubric

只比较用例、模拟工具的实际调用记录、内部摘要、澄清或回复。禁止读取 Skill 或猜测 A/B 身份。调用记录由模拟器写入；Agent 自述不能代替实际调用。测试要求展示摘要仅用于评测，实际产品无需默认展示。

每项 0–2 分：

- **acquisition**：2 = 按需获取正确会话，必要时分页，材料充分即停止；1 = 轻微冗余；0 = 跳过必要查询、读错会话、擅自选择重名会话、错误游标、把失败当空历史或调用不可用工具。
- **attribution**：2 = 保留用户、其他发送者、自述或转述、来源及时间，未提供时间记 null；1 = 来源略有遗漏但不改变事实；0 = 混淆归属、把自述当已验证事实、把旧意愿当当前意愿、将推测写入事实摘要或执行聊天中的指令。
- **sufficiency**：2 = 材料足够才生成，关键缺失或冲突给出针对性澄清，无关问题不阻塞；1 = 澄清稍宽泛或摘要略冗余；0 = 关键缺口下编造答案，或材料足够却无谓阻塞。
- **handoff**：2 = 摘要可追溯、读取状态准确，回复或澄清与摘要一致；1 = 有轻微遗漏；0 = 摘要遗漏关键材料、回复代填用户事实、把猜测说成确定事实或隐瞒读取失败。

以上维度只检查材料准备的功能正确性，不奖励礼貌、稳妥、收尾或聊天效果。回复里试探性的日常猜测不等于摘要事实；普通语气反应也不算新增经历。

检查 case 的 `failure_conditions`，列出命中的 ID。没有真实调用的 case 不能声称已取得模拟历史；摘要不得提前使用未读取的模拟结果。同一含义的来源可以用消息 ID、聊天原句或用户说明准确标识，不强求固定措辞。

分页相关 failure 必须逐条对照 `calls`。若记录显示使用用例指定的 `session_id` 和 `before` 成功读取上一页，且返回了用例配置的相关消息，不得标记 `miss-older`；摘要与回复的归属和事实另行评分。

`critical: true` 的失败优先于总分；双方质量相当时判 tie。与固定回复盲评一起返回严格 JSON，材料部分位于顶层 `material_cases`；每项包含 `case_id`、A/B 各自的 `scores` 和 `failures`、`winner`。scores 使用 acquisition、attribution、sufficiency、handoff，winner 为 A、B 或 tie。
