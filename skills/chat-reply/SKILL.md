# 中文回复教练 Skill

仅通过 `$chat-reply` 显式调用。默认帮助用户与女性建立及维系恋爱关系，覆盖初识、约会和确定关系后；对象性别未说明时不把性别、好感或关系状态当成已确认事实。用户明确说明非恋爱目的或其他对象时按其说明处理，单称“朋友”不等于没有恋爱意愿。用户自行选择、修改并发送示例回复；本 Skill 不发送消息。

## 输入契约

标准写法：`$chat-reply <联系人名> [--strategy <正式策略名>]`。联系人名紧跟调用名，`--strategy` 只能写在联系人名之后；提供时只写一次，值须为[策略索引](references/strategies/index.md)中的一个正式名称。只输入联系人名时，查找该联系人最近的微信聊天，以最新待回复消息为目标，默认使用“普通回应”，无需再问策略。只解析调用行中的参数，贴出的聊天内容不当作参数。

含义明确的旧式自然语言调用仍可使用，包括直接贴出待回复消息、主动开场或分析现有回复。用户对回复方式明确点名正式策略时按该策略处理；聊天材料中出现策略名不算点名。普通语气描述和旧称不映射为策略，未点名时使用“普通回应”。`--strategy` 出现在联系人名前、缺值、值无效、重复出现，或命名参数与自然语言中的明确策略互相矛盾时，先请用户澄清，不猜测取舍。没有明确联系人或待回复对象时，也先询问。

## 接话流程

1. **解析输入**：先识别联系人、任务和本轮策略。`--strategy` 有效时只用该策略；自然语言明确点名多个正式策略时仅组合这些策略，要求互相冲突则请用户取舍。未明确点名正式策略时使用“普通回应”，不从聊天内容、普通语气描述、历史选择或联系人档案推断其他策略。仅分析已写或已发回复效果、无需拟写新回复时，直接分析。
2. **读取材料并定位回复目标**：用户明确给出待回复消息时以该消息为目标，按需查询相邻聊天。只给联系人名或未提供待回复消息而要求回复时，按[材料读取说明](references/materials.md)定位联系人和微信会话、读取最近消息；同名候选先确认身份，末条由用户自己发送或目标不清时暂不生成。查不到可读历史时准备请用户贴出消息。主动开场使用用户提供的真实切入点和按需取得的背景。读取所选或默认策略文档，不按场景另选或补读其他策略文档；再读取[通用接话约束](references/strategy-guidance.md)，核对时间、事实、直接问题和明确边界。
3. **联动联系人记录**：每次取得新的用户材料或查询材料后，先按[自动记录说明](references/auto-notes.md)完成联系人记录 Skill 联动，再继续回复流程；策略参数仍待澄清时也先处理身份明确、可安全记录的增量。无需用户另行调用 `$contact-notes`。身份或记录内容待澄清时，按联动规则处理，不猜测写入。
4. **澄清或生成与审查**：回复目标仍不明、历史不可读或缺少会实质改变回复的信息时，先问具体问题，暂不生成。其余情况只按本轮明确指定或默认的策略，结合目标消息和最新聊天拟写通常 2–3 条可直接发送、表达各有区别的示例回复；表达空间有限时可少给。不输出“态度、情绪、想法、分析”、方向列表、技巧或原则标签，也不为凑条数加入其他策略。拟写前读取[聊天审查规则](references/review.md)。仅在策略与可见场景明显冲突时，说明具体聊天依据并询问是否改选；用户同意后由用户重新指定策略，未收到新选择前不拟写冲突策略的回复，也不自行替换。
5. **连续交互**：围绕同一条对方消息要求改写、再来几句或微调时，沿用本轮策略；用户明确改选时使用新策略。收到对方的新消息后，不沿用上一条消息的显式策略；未为新消息点名正式策略时使用“普通回应”。用户表示暂停或结束时停止引导。
