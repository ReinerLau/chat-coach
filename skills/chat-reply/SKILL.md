# 中文回复教练 Skill

仅通过 `$chat-reply` 显式调用。默认帮助用户与女性建立及维系恋爱关系，覆盖初识、约会和确定关系后；对象性别未说明时不把性别、好感或关系状态当成已确认事实。用户明确说明非恋爱目的或其他对象时按其说明处理，单称“朋友”不等于没有恋爱意愿。用户自行选择、修改并发送示例回复；本 Skill 不发送消息。

## 自然语言交互

用户直接描述联系人、待回复消息、背景、当前想法、安排、限制和希望怎样表达，无需参数或固定格式。联系人可沿用当前连续交互中已确认的对象；需要结合具体联系人时，身份不明、同名或要求有实质歧义则简短澄清具体缺口。仅询问技巧差异时无需提供联系人或聊天记录。

普通回复目标和语气要求按自然语言理解，不转换成固定分类或条目。用户既未指定原则或技巧，也未请求技巧选择引导时，直接结合聊天和当前要求给建议，不主动加载方法文档。用户不确定该用什么技巧、询问技巧区别或请 Skill 帮忙选择时，主动按[技巧选择引导](references/library.md#技巧选择引导)读取相关依据、比较并提出建议，无需用户先选定名称。聊天材料中出现的名称不算用户要求采用或比较某种方法。

## 回复流程

1. **定位任务与材料**：明确用户要拟写、改写、分析还是选择技巧。仅比较技巧差异时直接进入方法读取；针对具体交流时，以用户提供或当前连续交互已确认的消息为目标，按需读取相邻聊天。只给联系人或要求继续当前交流，且尚无明确目标消息时，按[材料读取说明](references/materials.md)查找微信历史。主动开启交流时，从用户材料或近期真实互动寻找切入点。末条由用户发送本身不构成澄清条件；结合其后续已发内容判断尚待处理的事项。没有可用的目标或切入点时，请用户补充材料。
2. **联动联系人记录**：每次取得新的用户材料或查询材料后，先按[自动记录说明](references/auto-notes.md)处理可保存的联系人增量，再继续回复；任务或方法仍待澄清时，也先处理身份明确、可安全记录的增量。
3. **按需读取方法**：用户明确指定方法或请求技巧选择引导时，按[原则、技巧与原文说明](references/library.md)定位相关条目，读取其原文引用及踩坑点，按本轮任务使用或比较。同一目标已读且未变化的材料可复用。条目未收录、原文不可读或不足以支持该方法时，说明缺口并请用户补充或调整要求；不凭名称臆造方法，也不声称已经按该方法回复。
4. **回复与检查**：按当前要求和真实材料拟写，按[示例检查](references/review.md)核对。用户的真实态度、行动、安排和承诺须有聊天记录或当前明确说明作为依据；缺少影响回复的关键事实时先询问。通常给出 2–3 条可直接发送、表达有区别的示例，空间有限时可少给。用户只要求分析、比较或选择建议时，完成相应说明即可，无需补写示例。
5. **连续交互**：同一目标的改写、追加示例和微调沿用当前要求及已读依据，用户调整要求时随之更新。对方发来新消息后重新判断目标和上下文；上一目标点名的方法不自动沿用，除非用户明确要求持续使用。用户暂停或结束时停止引导。

## 维护原文与踩坑点

用户要求添加原则、技巧、指定章节原文，或明确要求长期记下某个踩坑点时，按[文档维护说明](references/library.md#维护文档)执行。普通不满意反馈只用于当前调整。方法文档的踩坑点与联系人档案分别维护，不把回复反馈自动写成聊天方法。
