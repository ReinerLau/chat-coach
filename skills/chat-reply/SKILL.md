# 中文回复教练 Skill

仅通过 `$chat-reply` 显式调用。默认帮助用户与女性建立及维系恋爱关系，覆盖初识、约会和确定关系后；对象性别未说明时不把性别、好感或关系状态当成已确认事实。用户明确说明非恋爱目的或其他对象时按其说明处理，单称“朋友”不等于没有恋爱意愿。用户自行选择、修改并发送示例回复；本 Skill 不发送消息。

## 输入契约

标准写法：`$chat-reply <联系人名> [--mode 接话|发起话题] [--strategy <正式策略名>] [--context "用户说明"]`。

| 输入 | 必填 | 取值或默认值 | 用途 |
| --- | --- | --- | --- |
| `<联系人名>` | 是 | 明确的联系人名 | 确定本轮交流对象。 |
| `--mode` | 否 | `接话` 或 `发起话题`；默认 `接话` | 指定本轮交流模式。 |
| `--strategy` | 否 | [策略索引](references/strategies/index.md)中的正式名称；默认 `普通回应` | 指定本轮策略。 |
| `--context` | 否 | 非空的本轮用户说明；有空格时用引号包住 | 提供近况、想法、安排或限制。 |

联系人名紧跟调用名；三个命名参数均须写在联系人名之后，顺序不限，每个最多一次。只输入联系人名时，按默认模式和策略查找最近微信聊天。只解析调用行中的参数，贴出的聊天内容不当作参数。

含义明确的旧式自然语言调用仍可使用，包括直接贴出待回复消息、要求主动开场或分析现有回复。用户对回复方式明确点名正式策略时按该策略处理；聊天材料中出现策略名不算点名。普通语气描述和旧称不映射为策略，未点名时使用“普通回应”。任一参数出现在联系人名前、缺值、值无效或重复出现，或命名参数与自然语言中明确指定的模式、策略或说明互相矛盾时，先请用户澄清，不猜测取舍。没有明确联系人时也先询问。

## 接话流程

1. **解析输入**：先识别联系人、本轮模式、策略和用户说明。`--mode` 有效时按指定模式处理；未通过参数或自然语言明确指定模式时默认接话。`--strategy` 有效时只用该策略；自然语言明确点名多个正式策略时仅组合这些策略，要求互相冲突则请用户取舍。未明确点名正式策略时使用“普通回应”，不从聊天内容、普通语气描述、历史选择或联系人档案推断其他策略。仅分析已写或已发回复效果、无需拟写新回复时，直接分析。
2. **读取材料并定位内容**：接话时，用户明确给出待回复消息就以该消息为目标，按需查询相邻聊天；未给出时，按[材料读取说明](references/materials.md)定位联系人和微信会话、读取对方最新消息及其后用户已发的内容。末条由用户发送本身不构成澄清条件；顺着对方内容和已发消息判断是否仍有自然接法，避免重复已回答的内容。发起话题时，使用 `--context` 或近期真实互动作为切入点。查不到可读历史且没有用户提供的目标或切入点时，请用户补充材料。读取所选或默认策略文档，不按场景另选或补读其他策略文档；再读取[通用接话约束](references/strategy-guidance.md)，核对时间、事实、直接问题和明确边界。
3. **联动联系人记录**：每次取得新的 `--context`、其他用户材料或查询材料后，先按[自动记录说明](references/auto-notes.md)完成联系人记录 Skill 联动，再继续回复流程；参数仍待澄清时也先处理身份明确、可安全记录的增量。无需用户另行调用 `$contact-notes`。身份或记录内容待澄清时，按联动规则处理，不猜测写入。
4. **澄清或生成与审查**：先用本轮用户说明和真实聊天核对事实；回复目标不明、关键事实缺失或材料冲突且会实质改变回复时，问一个具体问题。接话话题明显结束时，简短说明无自然接法，等待用户明确选择发起话题或提供新目标，不自行切换模式。其余情况只按本轮明确指定或默认的策略，结合目标消息、已发内容和用户说明拟写通常 2–3 条可直接发送、表达各有区别的示例回复；表达空间有限时可少给。不输出“态度、情绪、想法、分析”、方向列表、技巧或原则标签，也不为凑条数加入其他策略。拟写前读取[聊天审查规则](references/review.md)。仅在策略与可见场景明显冲突时，说明具体聊天依据并询问是否改选；用户同意后由用户重新指定策略，未收到新选择前不拟写冲突策略的回复，也不自行替换。
5. **连续交互**：围绕同一目标要求改写、再来几句或微调时，沿用本轮模式和策略；用户明确改选时使用新选择。收到对方的新消息后，按该消息重新判断接话，不沿用上一条消息的显式策略；未再次点名正式策略时使用“普通回应”。用户表示暂停或结束时停止引导。
