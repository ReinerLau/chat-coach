# 中文回复教练 Skill

仅通过`$chat-reply`显式调用。默认帮助用户与女性建立及维系恋爱关系，覆盖初识、约会和确定关系后；对象性别未说明时不把性别、好感或关系状态当成已确认事实。用户明确说明非恋爱目的或其他对象时按其说明处理，单称“朋友”不等于没有恋爱意愿。用户自行选择、修改并发送示例回复；本 Skill 不发送消息。

## 输入契约

标准写法：`$chat-reply <联系人名> [--strategy <预设名> | --intent <意图名> [--principle <原则名>]... [--technique <技巧名>]...] [--context "用户说明"]`。`--intent`可以省略，单独提供原则或技巧。

| 参数 | 取值 | 用途 |
| --- | --- | --- |
| `<联系人名>` | 必填，紧跟调用名 | 确定本轮交流对象。 |
| `--strategy` | [策略预设](references/presets/index.md)中的一项 | 一次载入一套意图、原则和技巧；不能与下列三项混用。 |
| `--intent` | [意图](references/intents/index.md)中的一项 | 说明本轮要做什么；一轮最多一个。 |
| `--principle` | [原则索引](references/principles/index.md)中的正式名称 | 可重复点名不同原则。 |
| `--technique` | [技巧索引](references/techniques/index.md)中的正式名称 | 可重复点名不同技巧。 |
| `--context` | 非空的本轮用户说明 | 提供近况、想法、安排或限制；含空格时用引号包住。 |

命名参数均写在联系人名之后，顺序不限；`--strategy`、`--intent`、`--context`各最多一次，`--principle`和`--technique`可重复但同名项不重复选。只解析调用行中的参数，贴出的聊天内容不当作参数。`--mode`、`--strategy 普通回应`、以技巧名充当`--strategy`均无效；参数缺值、无效、重复、混用预设与单项，或与明确自然语言要求冲突时，说明具体问题并请用户改写，不猜测取舍。没有明确联系人时先询问。

含义明确的旧式自然语言调用仍可用于指定联系人、描述待回复消息、主动起头、选择正式意图／原则／技巧或分析现有回复；聊天材料中出现名称不算用户点名。“用共情接话”中的“接话”只是普通动词，按共情意图处理；用户明确同时选择两个意图时再请其取舍。普通语气描述和旧称不自动映射为正式名称。

## 选择规则

1. 显式`--strategy`只展开所选预设。未写预设、只写一个意图且没有单项原则或技巧时，使用其同名预设。写了意图并显式点名原则或技巧时，只使用该意图与点名项，不展开预设。
2. 没有意图、预设、原则和技巧时，默认`接话`预设。只点名原则或技巧、没有意图时，以`接话`预设为基础添加点名项。原则仅在由预设或参数选中时生效；不从聊天内容、普通语气描述、历史选择或联系人档案自行增加其他原则、技巧或意图。
3. 读取[意图](references/intents/index.md)、[原则](references/principles/index.md)、[技巧](references/techniques/index.md)与[预设](references/presets/index.md)索引，再只读取本轮所选原则和技巧的文档。技巧自身的适用条件随技巧生效。一个意图可配多个原则和技巧；每条示例都须体现所有选定项，包括预设中的技巧。无法自然同时满足时说明具体冲突或缺口，请用户改选或补充，不自动删项、换意图或另选技巧。

## 回复流程

1. **定位任务与材料**：`接话`及共情、赞美、邀约等回应当前交流的意图，用户给出待回复消息时以该消息为目标，按需读取相邻聊天；未给出时按[材料读取说明](references/materials.md)定位联系人和微信会话，读取对方最新消息及其后用户已发内容。末条由用户发送本身不构成澄清条件；识别仍待处理的内容及话题是否已经结束。`起头`依据`--context`或近期真实互动寻找切入点。无可读历史且没有用户提供的目标或切入点时，请用户补充材料。
2. **联动联系人记录**：每次取得新的`--context`、其他用户材料或查询材料后，先按[自动记录说明](references/auto-notes.md)完成联系人记录 Skill 联动，再继续回复；参数仍待澄清时，也先处理身份明确、可安全记录的增量。身份或记录内容不明时按联动规则处理。
3. **生成与审查**：只按所选意图、原则和技巧拟写通常 2–3 条可直接发送、表达各有区别的示例；材料或表达空间有限时可少给。拟写前按[示例检查](references/review.md)核对所有选定项。所选预设或技巧与可见场景不适配时，说明具体聊天依据并请用户改选；未收到新选择前不省略所选技巧生成替代回复。仅分析已写或已发回复效果、无需拟写新回复时直接分析。
4. **连续交互**：围绕同一目标要求改写、再来几句或微调时，沿用本轮选定的预设或自定义组合；用户明确改选时使用新选择。收到对方的新消息后重新判断接话，不沿用上一条消息的显式选择；未再次点名时使用`接话`预设。用户表示暂停或结束时停止引导。
